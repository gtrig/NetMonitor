# Cleanup, machines, network links, scan jobs — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Carry data over network renames and remove stale data, group several device rows into one machine, draw how networks connect (traceroute), and show live scan-job state.

**Architecture:** Per-network device rows stay as they are. A new `machine_members` table groups rows into machines, and the topology builder turns groups into single nodes. nmap gains an opt-in `--traceroute` and streamed progress. The scheduler exposes per-job state and an `/api/jobs` endpoint for a polling panel.

**Tech Stack:** Go 1.26, modernc.org/sqlite, html/template, vanilla JS, Cytoscape.js 3.30.4 (compound nodes, `cose` layout).

**Spec:** `docs/superpowers/specs/2026-11-22-multinet-design.md`

## Global Constraints
- No new Go modules and no new JS libraries; Cytoscape stays vendored.
- Database changes are new entries appended to `migrations` in `internal/store/store.go`; existing migrations are never edited.
- Mutating data endpoints sit behind the existing auth and CrossOriginProtection. Stale-data merge/delete also require `canEdit()` (auth configured).
- Events are never deleted.
- `go vet ./...` and `go test ./...` stay green after every task.

## Review Focus
1. Renaming a network into a name that already has data (exactly the user's `lan` → `GTLan` case): no duplicate rows, no lost labels, no baseline storm.
2. A machine member whose key changes (IP-only → MAC) or is merged away by the store keeps or drops its membership correctly.
3. The same IP appearing both as a traceroute hop (`router` ref) and as a device must resolve to one node, not two.
4. nmap progress parsing must not break XML parsing when `<taskprogress>` lines are interleaved.
5. Job state transitions (queued → running → idle) and next-run time stay correct after **Scan now** and after a hot reload.

### Task 1: Store — cleanup operations and machine membership

**Files:** Modify `internal/store/store.go`, `internal/store/devices.go`, `internal/model/model.go`. Create `internal/store/cleanup.go`, `internal/store/machines.go`. Tests in `internal/store/store_test.go`.

**Interfaces (produces):**
- `model.MemberRef{Network, Key string}`
- `(*Store) RenameNetwork(ctx, from, to string) error`: one transaction.
  - **Devices:** a `to` row with the same key wins and fills an empty label (and `known` = max) from the `from` row. The remaining `from` rows move to `to`.
  - **Events:** network is updated.
  - **Links:** the `from` rows are deleted, since the next scan recreates them.
  - **network_state:** keeps `to`'s row when it exists; otherwise renames `from`'s.
  - **machine_members:** same rule as network_state.
- `(*Store) DataNetworks(ctx) ([]NetworkData, error)`, where `NetworkData{Name string; Devices, Events int}` covers every network name found in devices ∪ events ∪ network_state.
- `(*Store) DeleteNetworkData(ctx, name string) error`: deletes the network's devices, links, network_state and machine_members; keeps its events.
- `(*Store) DeleteDevice(ctx, network, key string) error`: returns `ErrNotFound` when the row is missing, and also deletes its membership.
- Migration 3: `CREATE TABLE machine_members (network TEXT NOT NULL, key TEXT NOT NULL, machine_id INTEGER NOT NULL, PRIMARY KEY (network, key)); CREATE INDEX machine_members_id ON machine_members(machine_id);`
- `(*Store) Machines(ctx) (map[model.MemberRef]int64, error)`
- `(*Store) MergeMachine(ctx, refs []model.MemberRef) (int64, error)`:
  - Needs at least 2 refs, all of them existing devices, otherwise an error.
  - The new machine uses the smallest existing machine id among the refs, or `MAX(machine_id)+1`.
  - Every member of the other machines involved moves into it.
- `(*Store) SplitMember(ctx, ref model.MemberRef) error`: removes the ref from its machine, then deletes any machine left with fewer than 2 members.
- `UpsertDevices` keeps membership in step:
  - With `PrevKey`, the membership key is renamed. `UPDATE OR IGNORE` is used, and the old key is deleted afterwards.
  - With `MergedInto`, the deleted row's membership moves to the target unless the target already has one; any leftover is then deleted.

**Interfaces:**
- In `source`:
  - `type Progress struct{ Task string; Percent float64 }`
  - `WithProgress(ctx, func(Progress)) context.Context`
  - `ReportProgress(ctx, Progress)`, which does nothing without a callback.
- `nmap.New(args []string, traceroute bool, exec ExecFunc)`.
- `nmap.BuildArgs(user []string, traceroute bool, cidr netip.Prefix)` always adds `--stats-every 2s`, plus `--traceroute` when asked.
- `nmap.ParseProgress(line string) (Progress, bool)` reads `<taskprogress task="Ping Scan" ... percent="23.45" .../>`.
- `DefaultExec` streams stdout line by line: each line is buffered and also passed to `ParseProgress` → `ReportProgress`.
- `scheduler.JobStatus` gains:
  - `ID int`, the job index.
  - `State string`: `idle`, `queued` or `running`.
  - `StartedAt`, `NextRun time.Time`.
  - `Progress *float64` and `Task string`, both `omitempty`.
  - `LastDuration float64`, in seconds.
- State and timing rules:
  - `NextRun` is set to now + Interval after each run; **Scan now** also resets it.
  - A job is `queued` while it waits for the concurrency semaphore.
  - `Progress` and `Task` are cleared when a run ends.
- `(*Scheduler) ScanJob(id int) error` returns `ErrUnknownJob` for an id that doesn't exist.
- Web endpoints:
  - `GET /api/jobs` → `[]JobStatus`.
  - `POST /api/jobs/{id}/scan` → 202, or 404 for an unknown job.
- **Dashboard:** a **Scan jobs** table after the network cards. jobs.js polls `/api/jobs` every 2 s and ticks the timers every 1 s. Columns:
  - Network, Source, State (badge).
  - While running: elapsed time plus a progress bar with the task name, or a spinner when no percentage is known.
  - Next run (countdown), last duration, last error.
  - A **Scan now** button.

### Task 5: Topology — machines, hop resolution, all-networks compound view

**Files:**
- `internal/topology/topology.go` (+ test)
- `internal/web/server.go` (apiGraph)
- `internal/web/static/map.js`
- `internal/web/templates/map.html`
- `internal/web/static/style.css`

**Interfaces:**
- `topology.Input{Devices []model.Device; Links []model.Link; Gateways map[string]string; Machines map[model.MemberRef]int64; Networks []NetInfo; Compound bool}`, with `NetInfo{Name string; CIDR netip.Prefix}`.
- `topology.Build(in Input) []Element`.

**Node rules:**
- **Grouping:** device rows in a machine become one node `machine:<id>`. Other rows become `device:<key>`, and rows that share a key across networks share that node.
- **Node data:**
  - `kind:"device"`, plus `router:true` when the node appears as a hop.
  - `networks []string`.
  - `members []{network, key, ip, mac}`.
  - `ip`: member IPs joined with ", ".
  - `status`: online if any member is online.
  - `known`: true only if all members are.
  - `label`: the first non-empty member label, then hostname, then IP.
- **Resolving link refs:**
  - A `router` ref whose ID parses as an IP → the node owning that IP, if any. Otherwise a `hop:<ip>` node (`kind:"hop"`), placed in the configured network whose CIDR contains the IP.
  - A `device` ref with a key or `ip:` → the node owning it.
  - A `router` ref with a config name → `router:<name>`, as today.
- **Compound mode** (the all-networks view):
  - One `net:<name>` node (`kind:"net"`, label "name cidr") per configured network plus each device network.
  - A node in exactly one network gets `parent: net:<name>`.
  - A node in several networks gets no parent, and a `member` edge (`kind:"member"`) to each network.
  - No gateway or network fallback edges.
- **Non-compound mode** keeps the current gateway/network fallback.
- **apiGraph:** compound when no `network` param is given and more than one network is configured. It passes the machines from the store and the networks from the config.
- **map.js:**
  - Styles: `node[kind='net']` (compound box with its label at the top), `node[kind='hop']` (small grey diamond), `node[?router]` (router shape), `edge[kind='member']` (dashed).
  - The panel lists every member (network, IP, MAC) for machines.
  - Layout: `cose` with `nestingFactor` set for compounds.
