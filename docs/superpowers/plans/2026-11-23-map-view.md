# Map View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A cleaner map with three layouts, display checkboxes, and device distance from router-measured ping times.

**Architecture:** A new ping job kind in the scheduler stores smoothed times; the graph API exposes them per network. Pure layout functions compute positions, which Cytoscape shows as a preset layout over a canvas of rings, wedges or lanes.

**Tech Stack:** Go 1.26, SQLite, Cytoscape, plain JS, Tailwind 4 (`npm run css`), `node --test`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-23-map-view-design.md`

## Global Constraints
- Work on branch `map-view`. Nothing is pushed or deployed.
- Pings: every 5 minutes, 3 per device, one device at a time, own API connection, online IPv4 devices only.
- Run result: median of answered pings. Value: median of answered runs among the last 5; none when the latest 3 runs all missed.
- Pings never change online/offline state and never create events.
- Log scale 0.1–300 ms, clamped. Never mix origins in one network.
- Default layout Radar. Defaults on: names, rings, lines, offline, distance. Off: IPs, ping times, port names.

## Clarifications to the spec (made while planning)
- **Routers are drawn at the centre of the LAN they serve**, not in the VPN. The spec's "in its transit network" would leave a LAN radar without its centre. Their VPN link is a line. Other multi-network machines stay as specified.
- **One origin per network:** its first configured router (`Runtime.Gateways`). Times from two routers in one radar would not be comparable.

## Review Focus
1. Router refuses `/ping`: ARP job unaffected, map shows why (Task 2, Task 6).
2. Device key changes or a merge happens between reading and saving: the time is not saved under a dead key (Task 1, Task 3).
3. Slow or unreachable hosts: a run never hangs and other hosts are still measured (Task 2).
4. Network with no router, no ping data, or a single device: still laid out, no NaN positions (Task 5).
5. Browser storage blocked or holding bad JSON: map loads with defaults (Task 6).

### Task 2: RouterOS pinger

**Interfaces — Produces:**

### Task 3: Ping jobs and nmap times
**Files:** Create `internal/scheduler/pings.go`, `pings_test.go`; modify `scheduler.go`, `app/app.go`, `source/source.go`, `source/nmap/parse.go`, `model/model.go`, and their tests.

**Interfaces — Consumes:** Tasks 1, 2. **Produces:**
- `scheduler.Pinger` interface with the three Task 2 methods; `Job.Ping Pinger`
- `model.Host.RTT time.Duration` (from nmap `srtt` microseconds, 0 = unknown), kept by `source.Merge`/`combine`
- `scheduler.PingInterval = 5 * time.Minute`; nmap origin string `"netmon"`

`DefaultBuild` adds one ping job per network with a gateway router. `runPings` pings online IPv4 devices, then re-reads devices and maps answers by IP to current keys before recording; silent devices record a miss. A run with no targets is a success. ### Task 5: Layout functions
**Files:** Create `internal/web/static/map-layout.js`, `internal/web/jstest/map-layout.test.js` (outside `static`, so it is not embedded); modify `package.json` (`"test": "node --test internal/web/jstest/"`).

**Interfaces — Produces:** global `MapLayout` (also `module.exports`):
- `frac(ms) → 0..1`
- `groups(els) → [{network, label, centre, nodes}]`; `centre` is the `gatewayOf` node id, or `"netmon:" + network` (a marker the page adds)
- `layout(mode, els, {distance, offline}) → {positions: {id: {x, y}}, decor: [{network, kind: "ring"|"outer"|"wedge"|"lane"|"tick", …, label}]}`, mode `radar|sectors|lanes`

Group arrangement reuses the rule in `boxLayout`: most-connected network in the middle, others around it; lanes stack vertically. A device in several networks belongs to its graph `parent`, else its first network. A gateway of several networks centres the first; the others use a `netmon:` marker. Radar angles: devices sorted by id, placed by golden-angle index. Wedge minimum 0.35 rad, capped so the total fits. Radius grows with device count. Hops and other nodes without a group go in a row underneath.

- [ ] Write tests: `frac` (0.1→0, 300→1, 0→0, 5000→1, 10≈0.575); greater ms is never nearer in all modes; offline and no-ping online at the same outer distance; changing a device's ms keeps its radar angle; `distance:false` gives equal radii; `offline:false` omits offline ids; wedges do not overlap and stay within 2π for 12 ports; a missing port groups as `no port`; groups' bounding boxes do not overlap; empty graph, one device, no router and no ping data give finite positions; a gateway of a LAN centres it even when its parent is the VPN.
- [ ] Run `npm test` → fails. Implement. Run → PASS. Commit `feat(map): layout functions`.

### Task 6: Map page
**Files:** Modify `internal/web/static/map.js`, `internal/web/templates/map.html`, `internal/web/styles/app.css` (`@source`), generated `static/app.css`, `README.md`, `internal/web/server_test.go`; create `internal/web/static/map-options.js`, `internal/web/jstest/map-options.test.js`.

**Interfaces — Consumes:** `MapLayout`, graph `rtt`/`gatewayOf`, `/api/jobs`. **Produces:** `MapOptions.load(storage)`, `MapOptions.save(storage, o)`, `MapOptions.DEFAULTS`, key `netmon.map.v1`; keys `layout,names,ips,ms,ports,rings,lines,offline,distance`.

- Toolbar: layout dropdown (Radar, Port sectors, Distance lanes), `Display` popover with the eight checkboxes in spec order, closable with Escape and outside click. Re-layout button becomes `Reset view`.
- Positions applied with Cytoscape `preset`. A canvas behind the graph redraws on `render`, following pan and zoom. Compound boxes become invisible apart from their label and stay clickable; nodes move to their layout group's box.
- Labels are composed from names, IPs, ms. Port names show on lines in radar, once per wedge or lane otherwise. Overlapping labels are hidden, by priority (router, hovered/selected, then device id), recalculated after zoom.
- The 60 s refresh updates data, animates moves over 400 ms (none with reduced motion), and keeps pan, zoom and selection, also when nodes are added or removed. Fit happens only on first load, network or layout change, and Reset view.
- Panel rows: `Ping` (`0.4 ms from GTHOME, 2m ago`, one per network, or `no reply`).
- A `ping:` job with `lastErr` shows a notice bar under the toolbar with the network and the error. No data yet shows `Waiting for the first ping run`.
